# rnaseq-rc Wrangler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an `rnaseq-rc` user dataset type that turns two or three uploaded files (counts + sample metadata) into an EDA-loadable study with a `sample` entity and a tall `HTSeq counts` entity.

**Architecture:** Count-file handling is fully deterministic and has no LLM awareness. A single LLM-dependent step generates a sample annotation JSON, which is converted to STF and read back as an entity; it gets exactly one retry on validation failure. Study assembly and final validation are deterministic.

**Tech Stack:** R (`tidyverse`, `study.wrangler`, `httr`, `jsonlite`, `yaml`, `testthat`), Docker Compose, Claude Messages API.

**Design spec:** `docs/superpowers/specs/2026-07-29-rnaseq-rc-design.md` — read this first. It is authoritative where this plan is silent.

## Global Constraints

- **Datatype name is `rnaseq-rc`.** Never `bulk-rnaseq-counts` (a former name).
- **Entity names:** `sample` (root) and `HTSeq counts` (child of `sample`). The space in `HTSeq counts` is correct and validated.
- **Stable IDs are a fixed integration contract:** `VEUPATHDB_GENE_ID`, `SEQUENCE_READ_COUNT_SENSE`, `SEQUENCE_READ_COUNT_ANTISENSE`, `SEQUENCE_READ_COUNT`.
- **No new R package dependencies.** `httr`, `jsonlite`, `yaml`, `testthat`, `withr`, `readr` are all already installed. Adding a dependency means editing the Dockerfile and a ~45 minute rebuild.
- **Never modify `bin/`.** It is not volume-mounted (see `docker-compose.override.yml`), so every change costs a ~45 minute rebuild. All new code goes in `lib/R/`, which is mounted. `bin/wrangle.R` already does everything we need: it resolves the datatype, sources `lib/R/wrangle-<datatype>.R`, calls `wrangle(input_dir)`, then validates and exports.
- **Models:** `claude-sonnet-5` for annotation generation, `claude-haiku-4-5-20251001` for sample-ID classification.
- **Do NOT load the `claude-api` skill at top level.** It is a large context drain. Only the Task 1 subagent loads it, inside its own context.
- **Follow the code, not the docs, for study-wrangler.** `R/Entity-metadata-defaults.R` declares the authoritative `data_type` levels: `id`, `string`, `number`, `date`, `longitude`, `integer`, `category`. There is no `boolean` or `decimal`.
- **Reference implementation is `/home/maccallr/work/study-dealer-nextflow/bin/wrangleRNASeq.R`.** Two other files on disk are STALE variants using a wide-entity + gene-collection representation we are NOT following: `study-wrangler/tmp/lee_gamb/wrangleRNASeq.R` and `expression-shepherd/R/wrangle-rnaseq.R`. Do not copy from either.
- **Run tests with:** `make test` (equivalently `docker compose run --rm -w /opt/veupathdb plugin bin/run_tests.R`). There are 74 existing passing tests; none may regress.
- **In tests `TESTTHAT=true`,** so `stop_*_error()` helpers call `stop()` instead of `quit()`. That is what makes them catchable.
- **Validation profiles are `c("baseline", "eda")`,** already set by both `bin/wrangle.R` and `test_examples.R`.

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `llm_mocks_init(input_dir)` → invisible `NULL`. Resets the registry, then loads `llm-mocks.json` from `input_dir` only if `Sys.getenv("WRANGLER_ALLOW_LLM_MOCKS") == "1"` and the file exists.
  - `llm_text(call_name, model, system_prompt, user_prompt, max_tokens = 4096)` → length-1 character. Raw assistant text.
  - `llm_json(call_name, model, system_prompt, user_prompt, max_tokens = 8192)` → parsed list. Calls `llm_text`, strips markdown fences, parses with `jsonlite::fromJSON(simplifyVector = FALSE)`.
  - `llm_mocks_exhausted()` → character vector of `call_name`s that still have queued responses. Used by tests to assert all mocks were consumed.

**Behaviour notes for the implementer:**
- The registry is a module-level environment, e.g. `.llm_mocks <- new.env(parent = emptyenv())`, holding one list per `call_name` used as a FIFO queue.
- `llm_text` pops the next queued response for `call_name` when the queue exists. If the queue exists but is empty, `stop()` with a message naming `call_name` — an unexpected extra call must fail loudly, never fall through to a paid API call.
- Mock values may be either a JSON string or a nested list. If a list, re-serialise with `jsonlite::toJSON(auto_unbox = TRUE)` so `llm_json` exercises its real parsing path.
- Real calls: `POST https://api.anthropic.com/v1/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`. Body: `model`, `max_tokens`, `system`, `messages = list(list(role = "user", content = user_prompt))`. Plain messages only — no tools.
- 3 attempts total, exponential backoff (1s, 2s) on HTTP 429 and 5xx. Do not retry 4xx other than 429.
- Missing `CLAUDE_API_KEY`, non-2xx after retries, or a response without `content[[1]]$text` → `stop_unexpected_error()` from `lib/R/error_helpers.R`.
- Fence stripping must handle ```` ```json ```` and bare ```` ``` ````, leading and trailing, with surrounding whitespace.

## Task 2: Count-file discovery and validation

**Files:**
- Create: `lib/R/counts_files.R`
- Test: `tests/testthat/test_counts_files.R`

**Interfaces:**
- Consumes: `stop_validation_error()` from `lib/R/error_helpers.R`.
- Produces:
  - `discover_counts_files(input_dir)` → `list(mode = "stranded"|"unstranded", paths = <named character>)`. `paths` always contains `sample_info`, plus either `sense` and `antisense`, or `unstranded`. Calls `stop_validation_error()` on any violation.
  - `read_sample_info_text(path)` → length-1 character containing the whole file, newlines preserved.
  - `read_counts_long(path)` → tibble with columns `Gene` (chr), `sample.ID` (chr), `Count` (int). Long format, one row per gene per sample. Calls `stop_validation_error()` on malformed content.
  - `read_and_merge_counts(discovered)` → tibble. Unstranded: `Gene`, `sample.ID`, `Count`. Stranded: `Gene`, `sample.ID`, `Sense.Count`, `Antisense.Count`. Validates that sense and antisense agree on both sample and gene sets.
  - `counts_sample_ids(merged)` → sorted unique character vector. The authoritative sample-ID set.

**Behaviour notes:**
- Recognised stems are exactly `sense-counts`, `antisense-counts`, `unstranded-counts`, `sample-info`, matched case-insensitively, with extension `.txt`, `.tsv` or `.csv` (any case).
- Violations, all `stop_validation_error()`: no count file; both stranded and unstranded present; only one of the stranded pair; a stem matching more than one file; missing or empty `sample-info.*`; any unrecognised `.txt`/`.tsv`/`.csv` file.
- Delimiter: read the first line; if it contains a tab use `"\t"`, else `","`. Explicit beats `read_delim`'s guessing, and it is testable.
- Read every cell as character (`col_types = cols(.default = "c")`, `name_repair = "minimal"`) so we own the error messages rather than getting readr's coercion warnings.
- Column 1 is the gene ID **by position**, regardless of its header (production HTSeq files have an empty first header cell). Rename it to `Gene`.
- Drop rows where `Gene` starts with `__` **before** validating counts — `__no_feature` rows are legitimate input, not errors.
- Then validate: ≥1 sample column; ≥1 remaining gene row; no duplicate `Gene`; every count cell matches `^\d+$` after trimming. Fail on blank, non-numeric, fractional, negative, or thousands-separated values.
- Go straight to long with `pivot_longer(-Gene, names_to = "sample.ID", values_to = "Count")`. Do **not** transpose to wide first — see the spec's "Reading strategy" section.
- Stranded merge: `full_join(by = c("Gene", "sample.ID"))` then assert no `NA` in either count column. A `full_join` plus assertion surfaces mismatches; production's `inner_join` silently drops them.

## Task 3: Annotation JSON to STF converter

**Files:**
- Create: `lib/R/annotations_to_stf.R`
- Test: `tests/testthat/test_annotations_to_stf.R`

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces:
  - `annotations_to_stf(annotations, output_dir)` → the TSV path, invisibly. Writes `entity-sample.tsv` and `entity-sample.yaml` into `output_dir`.
  - `infer_stf_type(values)` → `list(data_type =, data_shape =)`.

**Behaviour notes:**
- Port of `/home/maccallr/work/dataset-curator/skills/sample-annotations-to-stf/scripts/sample-annotations-to-stf.js`. Read it first.
- `annotations` is the parsed JSON: `profileSetName`, `factors` (named list of `displayName`/`definition`/`unit`), `samples` (list of `sampleId`/`label`/`factors`).
- TSV header: `sample.ID \\ Descriptors` (two literal backslashes — in R source that is `"sample.ID \\\\ Descriptors"`), then `label`, then one column per factor key with spaces replaced by dots.
- **Omit the `SRA.ID.s.` column** the JS emits. User uploads have no SRA accessions.
- YAML: `name: sample`, `display_name: Sample`, `display_name_plural: Samples`, `id_columns` = one entry `list(id_column = "sample.ID", entity_name = "sample")`, then `variables`, then empty `categories` and `collections`.
- **Serialise with `yaml::as.yaml()`, never string concatenation.** The JS emits `display_name: ${value}` unquoted, which breaks on any LLM-written `definition` containing a colon. This is the single most important deviation from the original.
- `label` is always `data_type: string`, `data_shape: categorical`, and never carries a unit — regardless of its values. Do not run it through `infer_stf_type`.
- `infer_stf_type`, ignoring empty/`NA` values: all `^-?\d+$` → `integer`/`continuous`; all numeric incl. exponent → `number`/`continuous`; all `^\d{4}-\d{2}-\d{2}$` → `date`/`continuous`; otherwise `string`/`categorical`. No values at all → `string`/`categorical`.
- Every variable gets `provider_label` (a list, so YAML renders a sequence) and `display_name`. `definition` and `unit` only when present in `factors`.

## Task 4: Sample annotation gates and DESeq check

**Files:**
- Create: `lib/R/sample_annotation.R`
- Test: `tests/testthat/test_sample_annotation.R`

**Interfaces:**
- Consumes: `llm_text`, `llm_json` (Task 1); `annotations_to_stf` (Task 3); `stop_validation_error`, `stop_transformation_error`, `stop_if_entity_invalid` (existing).
- Produces:
  - `classify_sample_ids(sample_ids)` → `"labels_informative"` or `"labels_uninformative"`. Calls `llm_text("classify_labels", ...)` with Haiku. Any unrecognised reply is treated as `labels_uninformative` (the safe direction: it demands an explicit mapping).
  - `check_ids_present_in_sample_info(sample_ids, sample_info_text)` → invisible `TRUE`, or `stop_validation_error()` naming the missing IDs.
  - `build_sample_entity(annotations, authoritative_ids)` → an Entity, or `stop()` with a diagnostic message. Writes STF to a temp dir, reads it back, runs the three gates.
  - `generate_sample_entity(sample_ids, sample_info_text)` → an Entity. Calls `llm_json("annotate", ...)` with Sonnet, tries `build_sample_entity`, retries once with the failure messages appended, then `stop_transformation_error()`.
  - `check_deseq_suitability(entity)` → invisible `TRUE`, or `stop_validation_error()`.
  - `annotation_prompt(sample_ids, sample_info_text, previous_errors = NULL)` → length-1 character.

**Behaviour notes:**
- Gates inside `build_sample_entity`, in order: (1) `stop_if_entity_invalid(entity)`; (2) every generated `sample.ID` ∈ `authoritative_ids`; (3) every `authoritative_ids` present in the entity. Gates 2 and 3 must name the offending IDs — those messages go into the retry prompt, so they must be specific enough to act on.
- `generate_sample_entity` catches errors from the first attempt, appends `conditionMessage` to the retry prompt via `annotation_prompt(..., previous_errors = ...)`, and tries once more. On second failure, `stop_transformation_error()`. When `length(sample_ids) > 30`, append to the user message: `"This dataset contains a lot of samples (N), which can challenge our AI-based processing."` with `N` substituted.
- `check_deseq_suitability`: let `vars` be the entity's variable names excluding the ID column and `label`. Suitable iff `n_samples >= 2` **and** at least one variable in `vars` has ≥2 distinct non-missing values. No type-awareness.
- `annotation_prompt` content is ported from `/home/maccallr/work/dataset-curator/skills/curate-bulk-rnaseq/resources/step-2-analyze-samples.md`: factor identification, `displayName`/`definition`/`unit` rules, unit stripping from values, label rules (no replicate numbers). It must state that `sampleId` values must come **verbatim** from the supplied authoritative list, and must request JSON only.
- After a successful `build_sample_entity`, set `label` metadata: `is_featured = TRUE`, `display_order = 1`, matching production.

    relocate(assay.ID, .before = sample.ID)

  entity <- entity_from_tibble(
    tbl,

    display_name_plural = "HTSeq counts",
